Build a RAG System in Node.js

Practical coding notes. Chat with your own PDF using Gemini, LangChain and Pinecone. Copy each step, paste it in order, and run.

Stack: Node.js, Gemini (embeddings + chat), Pinecone (vector DB), LangChain (PDF loader, splitter). Put your PDF in the project folder, for example nodejs_backend_notes.pdf.

Project Setup

Step 1: Create the project

Make a folder, open it in the terminal, and initialise it. The last command turns on ES module import syntax.

mkdir rag-system
cd rag-system
npm init -y
npm pkg set type=module

Step 2: Install all packages

npm i @google/genai @langchain/community @langchain/core @langchain/google-genai @langchain/pinecone @langchain/textsplitters @pinecone-database/pinecone dotenv pdf-parse readline-sync

Step 3: Get your API keys

Create a Gemini key in Google AI Studio and a Pinecone key in the Pinecone dashboard. Save both in a file named .env.

Never share your real keys or upload .env to GitHub. Add .env to .gitignore.
GEMINI_API_KEY=your_gemini_api_key_here
PINECONE_API_KEY=your_pinecone_api_key_here
PINECONE_ENVIRONMENT=us-east-1
PINECONE_INDEX_NAME=rag-pdf-index

Phase 1: Create the Pinecone Index

File: createIndex.js. Run this only once. The index is the "database table" that will hold your vectors.

Step 1: Import and connect to Pinecone

import 'dotenv/config';
import { Pinecone } from '@pinecone-database/pinecone';

const pc = new Pinecone({
  apiKey: process.env.PINECONE_API_KEY,
});

Step 2: Check if the index already exists

This stops the script from creating the same index twice.

async function createRagIndex() {
  const indexName = process.env.PINECONE_INDEX_NAME;

  const existingIndexes = await pc.listIndexes();
  const alreadyExists = existingIndexes.indexes?.some(
    (idx) => idx.name === indexName
  );

  if (alreadyExists) {
    console.log(`Index "${indexName}" already exists.`);
    return;
  }

Step 3: Create the index

dimension: 3072 must match the Gemini embedding size. cosine measures how similar two vectors are.

  await pc.createIndex({
    name: indexName,
    dimension: 3072,
    metric: 'cosine',
    spec: {
      serverless: {
        cloud: 'aws',
        region: 'us-east-1',
      },
    },
    waitUntilReady: true,
  });

  console.log(`Index "${indexName}" is ready!`);
}

Step 4: Run the function with error handling

createRagIndex().catch((error) => {
  console.error('Index creation failed:', error.message);
  process.exitCode = 1;
});

Run it with node createIndex.js

Phase 2: Store Vectors into the Vector DB

File: storeVectors.js. Flow: PDF → pages → chunks → embeddings → Pinecone.

Step 1: Load the environment and imports

import * as dotenv from 'dotenv';
dotenv.config();
import { Pinecone } from '@pinecone-database/pinecone';
import { PDFLoader } from '@langchain/community/document_loaders/fs/pdf';
import { RecursiveCharacterTextSplitter } from '@langchain/textsplitters';
import { GoogleGenerativeAIEmbeddings } from '@langchain/google-genai';
import { PineconeStore } from '@langchain/pinecone';

async function storePdfVectors() {

Step 2: Load the PDF file

The loader reads the PDF and returns one document per page.

  const PDF_FILE_PATH = './nodejs_backend_notes.pdf';
  const pdfLoader = new PDFLoader(PDF_FILE_PATH);
  const pdfDocs = await pdfLoader.load();

Optional: check that the PDF loaded.

  console.log(pdfDocs.length);

Step 3: Split the PDF into chunks

Each chunk is up to 1000 characters. 200 characters overlap between chunks so no sentence loses its meaning.

  const splitter = new RecursiveCharacterTextSplitter({
    chunkSize: 1000,
    chunkOverlap: 200,
  });

  const chunks = await splitter.splitDocuments(pdfDocs);

Step 4: Set up the embedding model

The embedding model turns text into numbers (vectors) that capture meaning.

  const embeddings = new GoogleGenerativeAIEmbeddings({
    apiKey: process.env.GEMINI_API_KEY,
    model: 'gemini-embedding-2',
  });

Step 5: Connect to your Pinecone index

  const pinecone = new Pinecone();
  const index = pinecone.Index(process.env.PINECONE_INDEX_NAME);

Step 6: Embed the chunks and store them

This one call creates a vector for every chunk and uploads it to Pinecone with its text.

  await PineconeStore.fromDocuments(chunks, embeddings, {
    pineconeIndex: index,
    maxConcurrency: 5,
  });

  console.log('All chunks stored in Pinecone!');
}

storePdfVectors();

Run it with node storeVectors.js

Phase 3: Query Resolving (Ask Questions)

File: chat.js. Flow: user question → rewrite → embed → search Pinecone → send context to Gemini → answer.

Step 1: Imports and Gemini client

import * as dotenv from 'dotenv';
dotenv.config();
import readlineSync from 'readline-sync';
import { GoogleGenerativeAIEmbeddings } from '@langchain/google-genai';
import { Pinecone } from '@pinecone-database/pinecone';
import { GoogleGenAI } from '@google/genai';

const ai = new GoogleGenAI({ apiKey: process.env.GEMINI_API_KEY });

Step 2: Create the chat history

This array remembers earlier questions and answers, so follow-up questions work.

const chatHistory = [];

Step 3: Rewrite the follow-up question

A question like "explain more" means nothing alone. This function uses the history to turn it into a full standalone question before searching.

async function rewriteQuery(question) {
  chatHistory.push({
    role: 'user',
    parts: [{ text: question }],
  });

  const response = await ai.models.generateContent({
    model: 'gemini-3.1-flash-lite',
    contents: chatHistory,
    config: {
      systemInstruction: `
You are an expert in conversational query reformulation.
Your job is to analyze the conversation history and identify the actual intent behind the user's latest question.
Rewrite the latest question so that it is clear, self-contained, and understandable without requiring any previous messages. Use relevant details from earlier conversations whenever necessary to resolve references, missing context, or ambiguity.
Do not answer the question, provide explanations, or add any extra commentary.
Return only the rewritten question.
`,
    },
  });

  chatHistory.pop();
  return response.text;
}

Step 4: Start the main chat function and embed the question

Use the same embedding model as Phase 2, otherwise the vectors will not match.

async function askQuestion(question) {
  const standaloneQuestion = await rewriteQuery(question);

  const embeddings = new GoogleGenerativeAIEmbeddings({
    apiKey: process.env.GEMINI_API_KEY,
    model: 'gemini-embedding-2',
  });

  const questionVector = await embeddings.embedQuery(standaloneQuestion);

Step 5: Search Pinecone for similar chunks

topK: 10 returns the 10 chunks closest in meaning to the question.

  const pinecone = new Pinecone();
  const index = pinecone.Index(process.env.PINECONE_INDEX_NAME);

  const searchResponse = await index.query({
    topK: 10,
    vector: questionVector,
    includeMetadata: true,
  });

Step 6: Build the context text

Join the text of all matched chunks into one string. This is the "Retrieval" part of RAG.

  const contextText = searchResponse.matches
    .map((match) => match.metadata.text)
    .join('\n\n---\n\n');

Step 7: Save the user question in history

  chatHistory.push({
    role: 'user',
    parts: [{ text: question }],
  });

Step 8: Generate the answer with system instructions

The system instruction tells Gemini to answer only from the retrieved context. This is the "Generation" part, and it stops made-up answers.

  const response = await ai.models.generateContent({
    model: 'gemini-3.1-flash-lite',
    contents: chatHistory,
    config: {
     systemInstruction: `
You are a knowledgeable Node.js technical assistant working with a document-based question-answering system.

Answer the user's question by relying exclusively on the information provided in the retrieved context.

Follow these guidelines:
- Use the supplied context as your sole source of factual information.
- Do not introduce outside knowledge, assumptions, or unsupported details.
- If the context does not contain enough information to answer the question, respond exactly with:
  "I could not find the answer in the provided document."
- Present the answer in clear, concise, and easy-to-understand language.
- For technical topics, explain concepts accurately and include relevant details only when supported by the context.
- Do not mention internal retrieval processes or invent information to fill gaps.

Your priority is to provide a reliable answer that is fully supported by the available documents.
`,
    },
  });
To use this for another topic, change "Node.js expert" to your subject, such as a DSA teacher or a Python tutor.

Step 9: Save the answer and print it

  chatHistory.push({
    role: 'model',
    parts: [{ text: response.text }],
  });

  console.log('\n');
  console.log(response.text);
}

Step 10: Keep the chat running in a loop

async function main() {
  const userQuestion = readlineSync.question('Ask me anything--> ');
  await askQuestion(userQuestion);
  main();
}

main();

Run Order

Run these commands in this order. Phases 1 and 2 are one-time. Phase 3 is the chatbot you use daily.

node createIndex.js
node storeVectors.js
node chat.js
New PDF? Change PDF_FILE_PATH and run node storeVectors.js again. You do not need to create the index again.
